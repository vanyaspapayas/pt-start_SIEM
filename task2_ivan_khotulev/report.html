5. Отчёт об инциденте

5.1 Точка входа

Пользователь сам запустил скачанный C:\Users\VPupkin.domain\Downloads\launcher.bat (родитель explorer.exe). Это видно в 4688 (RecordID 15523440) и Sysmon 1 (210355007) в 13:14:42. Как файл попал в Загрузки, в логах не видно.

5.2 Этапы атаки

  1. 13:14:42 запуск launcher.bat через cmd.exe (pid 9512)
  2. 13:14:42 bat запускает скрытый PowerShell-загрузчик (pid 4044)
  3. 13:14:46 загрузчик скачивает агента с 10.158.3[.]4:9000
  4. 13:19:52 через ~5 минут злоумышленник через агента смотрит папку Documents
  5. 13:20:02 - 13:20:10 читает Advanced_Research_Report.docx и снова связывается с C2

Подробно в хронологии.

5.4 Действия

Злоумышленник не повышал права и не закреплялся (по этим логам). Сразу пошёл за данными: через агента посмотрел Documents, нашёл там документ и забрал его. Всё выполнялось в памяти PowerShell, на диске только launcher.bat.

5.5 Последствия

  • Утёк Advanced_Research_Report.docx (агент его прочитал и сразу связался с C2; объём передачи по Sysmon не видно).
  • Другие документы и файлы IPO_ в логах не тронуты.
  • Хост под контролем злоумышленника в правах пользователя, агент на момент конца логов ещё на связи.

5.6 Точка реагирования

Самый ранний надёжный признак это Sysmon 1 в 13:14:42.756: cmd.exe из bat в Downloads запускает powershell.exe -nop -ep bypass -w 1 -enc ....

  • Раньше нельзя: просто запуск bat-файла бывает и легитимным, будет много ложных.
  • Позже поздно: в 13:19:52 злоумышленник уже в документах, в 13:20:02 читает файл.
  • Окно для реакции около 5 минут. Изоляция хоста и блок 10.158.3.4 в это время предотвратили бы утечку.

5.7 Индикаторы

IoC

  • 10.158.3[.]4:9000
  • hxxp://10.158.3[.]4:9000/download/powershell/
  • C:\Users\*\Downloads\launcher.bat
  • командная строка powershell.exe -nop -ep bypass -w 1 -enc KABOAGUAdwAt...
  • Хэши cmd.exe и powershell.exe это штатные файлы Windows, как IoC не подходят

IoA

  • explorer.exe запускает cmd.exe с bat из Downloads / Temp, а тот запускает powershell.exe
  • PowerShell с -enc + -nop / -w 1 / -ep bypass
  • Net.WebClient, DefaultNetworkCredentials, iwr ... | iex
  • PowerShell сам подключается на нестандартный порт
  • PowerShell (4103) лазит по папкам пользователя и обращается к документам

6. Рекомендации

6.1 Поиск на других хостах

Запросы в Splunk (SPL) по тем же полям, что и в выгрузке:

Скрытый PowerShell с закодированной командой:

index=main orig_event="Sysmon 1" Image="*powershell.exe" CommandLine="*-enc*"
  (CommandLine="*-nop*" OR CommandLine="*bypass*" OR CommandLine="*-w 1*")
| table _time Computer User ParentCommandLine CommandLine

Запуск bat из Downloads / Temp:

index=main orig_event IN ("4688", "Sysmon 1") CommandLine="*cmd.exe*" (CommandLine="*\\Downloads\\*.bat*" OR CommandLine="*\\Temp\\*.bat*")
| table _time Computer CommandLine

Подключения к C2 и PowerShell на нестандартные порты:

index=main orig_event="Sysmon 3" (DestinationIp="10.158.3.4" OR (Image="*powershell.exe" NOT DestinationPort IN (80, 443, 3128, 8080)))
| table _time Computer Image ProcessId DestinationIp DestinationPort

Обращения PowerShell к документам и файлам IPO_:

index=main orig_event="PowerShell 4103" (Payload="*Advanced_Research_Report*" OR Payload="*Incident_Report*" OR Payload="*Expert_Services_Department*" OR Payload="*Product_Fails*" OR Payload="*IPO_*")
| table _time Computer Payload

Ещё запросы (PDQL, KQL) лежат в hunting_queries.md.

Что проверить на хосте

  • Downloads\launcher.bat и его Zone.Identifier, там видно откуда скачан
  • история браузера и почта пользователя за 28.11
  • Prefetch POWERSHELL.EXE, CMD.EXE, TIMEOUT.EXE; Amcache
  • полный журнал PowerShell (4103/4104) после 13:20
  • закрепление: Run / RunOnce, автозагрузка, задачи планировщика, службы, WMI-подписки
  • дамп памяти процесса 4044, если ещё жив

6.2 Сдерживание

  • Изолировать VPupkin.domain.com от сети
  • Заблокировать 10.158.3.4 на МСЭ и прокси; адрес внутренний, поэтому надо найти и изолировать этот хост
  • Сбросить пароль plat\VPupkin, завершить его сеансы

6.3 Устранение

  • Завершить powershell.exe 4044, удалить launcher.bat (сохранив копию для анализа)
  • Проверить закрепление, прогнать AV/EDR, лучше переустановить машину
  • Найти и удалить письмо / заблокировать ссылку, откуда скачан bat

6.4 Восстановление и на будущее

  • Запретить запуск скриптов (.bat, .ps1, .js, .vbs) из Downloads и Temp (AppLocker / ASR)
  • Включить PowerShell Script Block Logging (4104), сейчас код агента не виден
  • Проверить сбор 4688 и 4663: в выгрузке нет 4688 для powershell и нет 4663 на чтение документа от powershell
  • SACL и DLP на документы с префиксом IPO_
  • Запретить рабочим станциям выход на нестандартные порты, только через прокси
  • Включить правила корреляции из rules/

Вывод

Исходя из анализа выше, на компьютер был скачан файл launcher.bat, который при запуске создает powershell процесс, подключающий машину к 10.158.3[.]4:9000 C2, и оттуда даются команды для выгрузки конф. информации.

По данным логам, в момент сбора злоумышленник успел забрать Advanced_Research_Report.docx, другие документы еще не тронуты.
